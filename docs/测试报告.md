#### 4.2.1 环境兼容性问题（4 个）

##### BUG-01：HBuilderX 编译报错 — 可选链语法不兼容

| 项目 | 内容 |
|------|------|
| 现象 | HBuilderX 编译时报 `Unexpected token` 错误 |
| 根因 | 模板中使用了 `?.` 可选链语法（如 `m.user?.nickname`），HBuilderX 默认的 Vue 2 编译器不支持 ES2020 可选链 |
| 影响范围 | `club/detail.vue`、`activity/detail.vue` 等多个页面 |
| 修复方案 | 将 `?.` 改为辅助方法或 `if` 判断替代 |

##### BUG-02：HBuilderX H5 页面白屏

| 项目 | 内容 |
|------|------|
| 现象 | 微信小程序端可显示页面，H5 端完全白屏 |
| 根因 | `main.js` 使用了 Vue 3 的 `createSSRApp`，但 HBuilderX 默认使用 Vue 2 编译器 |
| 影响范围 | 整个 H5 端 |
| 修复方案 | 将 `main.js` 改为 Vue 2 标准写法 `new Vue({...App})` |

##### BUG-03：Pinia 模块缺失

| 项目 | 内容 |
|------|------|
| 现象 | HBuilderX 编译报 `文件查找失败：'pinia'` |
| 根因 | `main.js` 引入了 pinia，但 HBuilderX 原生项目未安装该依赖 |
| 影响范围 | 项目启动 |
| 修复方案 | 移除 pinia 引入（当前未使用 Pinia store） |

##### BUG-07：`@/` 路径别名在 HBuilderX Vue 2 中不生效

| 项目 | 内容 |
|------|------|
| 现象 | HBuilderX 编译时报路径解析失败，所有 `@/` 开头的 import 找不到模块 |
| 根因 | HBuilderX 原生 Vue 2 项目不支持 `@/` 路径别名（Webpack alias 未配置） |
| 影响范围 | 所有使用 `@/` 的页面和组件 |
| 修复方案 | 将全部 `@/` 路径改为相对路径（如 `../../utils/api.js`） |

| 现象 | 我的活动页面中，已签到和未签到的活动混排，用户难以找到待签到活动 |
| 根因 | 接口未返回签到状态，前端无排序逻辑 |
| 修复方案 | 接口增加 `checkedIn` 字段，前端将未签到活动排在前面 |

##### BUG-20：签到码可被关闭后允许无码签到

| 项目 | 内容 |
|------|------|
| 现象 | 活动启用签到码后，组织者可"关闭"签到码，导致参与者可无码签到 |
| 根因 | 签到码功能设计缺陷：允许关闭状态回退 |
| 修复方案 | 重新设计签到码生命周期——一旦启用，只能"刷新"（换新码）或"停止"（结束活动签到），不可关闭 |

##### BUG-21：社团创建按钮文案误导

| 项目 | 内容 |
|------|------|
| 现象 | 社团创建按钮显示"创建社团"，成功提示"创建成功"，但实际需管理员审批 |
| 根因 | 引入审批机制后未同步更新前端文案 |
| 修复方案 | 按钮改为"申请创建"，成功提示改为"申请已提交，等待管理员审核" |

##### BUG-23：重新申请页面包含无关字段

| 项目 | 内容 |
|------|------|
| 现象 | 社团被驳回后重新申请时，页面包含公告、状态等不应编辑的字段 |
| 根因 | 复用了社团编辑页面，未针对重新申请场景做裁剪 |
| 修复方案 | 创建专用的重新申请页面，仅包含名称、描述、分类等可修改字段 |

##### BUG-26：管理员驳回社团无需填写理由

| 项目 | 内容 |
|------|------|
| 现象 | 管理员驳回社团申请时无需填写理由，申请者不知被驳回原因 |
| 根因 | 驳回接口未要求 reason 字段 |
| 修复方案 | 驳回时强制要求填写理由，存入 `rejectReason` 字段，申请者可查看 |

#### 4.2.5 审批流程缺陷（3 个）

##### BUG-13：社团创建无审批流程

| 项目 | 内容 |
|------|------|
| 现象 | 任何用户创建社团即立即生效，无管理员审核 |
| 根因 | 初版开发未实现审批流程 |
| 影响范围 | 社团创建 |
| 修复方案 | 社团创建后状态设为 `pending`，管理员在后台审批（通过/驳回），通过后状态改为 `active` |

##### BUG-24：被驳回社团无法撤回/注销

| 项目 | 内容 |
|------|------|
| 现象 | 社团申请被驳回后，申请者无法撤回或注销该申请，残留数据 |
| 根因 | 审批流程未设计撤回/注销功能 |
| 修复方案 | 添加"撤回"功能，撤回后永久删除该社团记录 |

##### BUG-27：被驳回社团在"我的社团"中不可点击

| 项目 | 内容 |
|------|------|
| 现象 | 被驳回的社团在我的社团列表中显示但不可点击，用户无法查看驳回原因或进行后续操作 |
| 根因 | 列表项点击事件未处理 `rejected` 状态的社团 |
| 修复方案 | 点击被驳回社团弹出驳回原因弹窗，提供"重新申请"和"撤回"操作入口 |

#### 4.2.6 通知系统缺失（7 个）

##### BUG-22：自动通过报名未发送通知

| 项目 | 内容 |
|------|------|
| 现象 | 活动报名设置为自动通过时，报名者未收到任何通知 |
| 根因 | 自动通过路径遗漏了通知逻辑 |
| 修复方案 | 在自动通过报名时向报名者发送"报名已通过"通知 |

##### BUG-25：社团创建未通知管理员

| 项目 | 内容 |
|------|------|
| 现象 | 用户提交社团创建申请后，管理员无任何通知，需手动检查 |
| 根因 | 通知功能遗漏 |
| 修复方案 | 社团创建时向所有管理员（role=admin）发送通知 |

##### BUG-28：社团重新提交未通知管理员

| 项目 | 内容 |
|------|------|
| 现象 | 社团被驳回后重新提交申请，管理员无通知 |
| 根因 | 重新申请路径遗漏了通知逻辑 |
| 修复方案 | 重新提交申请时向所有管理员发送通知 |

##### BUG-29：待审核报名未通知组织者

| 项目 | 内容 |
|------|------|
| 现象 | 活动报名设置为需审核时，组织者未收到审核提醒 |
| 根因 | 通知功能遗漏 |
| 修复方案 | 有待审核报名时向活动组织者发送通知 |

##### BUG-30：成员退出未通知社长

| 项目 | 内容 |
|------|------|
| 现象 | 社团成员主动退出时，社长未收到通知 |
| 根因 | 通知功能遗漏 |
| 修复方案 | 成员退出时向社长发送通知 |

##### BUG-31：社团撤回未通知管理员

| 项目 | 内容 |
|------|------|
| 现象 | 申请者撤回社团申请后，管理员不知情 |
| 根因 | 通知功能遗漏 |
| 修复方案 | 撤回社团时向所有管理员发送通知 |

##### BUG-32：通知点击已删除社团导致报错

| 项目 | 内容 |
|------|------|
| 现象 | 点击与已撤回/删除社团相关的通知时，跳转到社团详情页报错 |
| 根因 | 通知跳转未检查目标社团是否仍存在 |
| 修复方案 | 跳转前检查社团是否存在，若已不存在则弹出提示"该社团已不存在" |
