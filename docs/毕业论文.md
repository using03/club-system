# 基于 Uniapp 的校园社团活动管理小程序的设计与实现

---

**摘要**

随着高校社团活动日益丰富，传统的线下管理方式已难以满足信息化需求。本文设计并实现了一套基于 Uniapp 的校园社团活动管理小程序系统，采用前后端分离架构，前端使用 Uniapp 框架开发，支持 H5 和微信小程序双端运行；后端使用 Node.js + Express 框架构建 RESTful API，数据库选用 MongoDB 存储半结构化的活动图文数据。系统涵盖社团信息展示、社团审核管理、活动发布与报名、签到码签到验证、活动评价反馈、站内消息通知等核心功能模块，共实现 20 个前端页面、43 个后端 API 接口、7 个数据模型。经测试验证，系统功能完整，运行稳定，能够有效提升校园社团活动的管理效率和参与体验。

**关键词：** Uniapp；微信小程序；社团管理；Node.js；MongoDB；签到码

---

**Abstract**

With the increasing variety of campus club activities, traditional offline management methods can no longer meet the demands of informatization. This paper designs and implements a campus club activity management mini-program system based on Uniapp, using a front-end and back-end separated architecture. The front-end is developed with the Uniapp framework, supporting both H5 and WeChat Mini Program platforms; the back-end is built with Node.js + Express framework providing RESTful APIs, with MongoDB as the database for storing semi-structured activity content including images and text. The system covers core functional modules including club information display, club approval management, activity publishing and registration, check-in code verification, activity feedback, and in-app notification center. A total of 20 front-end pages, 43 back-end API endpoints, and 7 data models are implemented. Testing verifies that the system is functionally complete and operationally stable, effectively improving the management efficiency and participation experience of campus club activities.

**Keywords:** Uniapp; WeChat Mini Program; Club Management; Node.js; MongoDB; Check-in Code

## 第1章 绪论

### 1.1 研究背景与意义

高校社团是校园文化的重要组成部分，是学生课外活动的主要阵地。随着社团数量的增长和活动形式的多样化，传统的社团管理方式——依赖纸质登记、微信群通知、人工统计——暴露出诸多问题：信息传递不及时、报名统计效率低、签到易作弊、活动反馈无闭环等。

移动互联网和小程序技术的快速发展为解决上述问题提供了新的途径。微信小程序凭借"无需下载、即用即走"的特点，天然适合校园场景的轻量级应用。同时，跨平台开发框架 Uniapp 的成熟使得"一次开发，多端部署"成为可能，大大降低了开发和维护成本。

本课题旨在设计并实现一套基于 Uniapp 的校园社团活动管理小程序，通过数字化手段解决社团管理中的痛点，提升管理效率和用户体验。

### 1.2 国内外研究现状

在社团管理信息化方面，国内外已有一定研究和实践：

**国外方面：** 国外高校普遍使用成熟的 SaaS 平台（如 CampusGroups、OrgSync）进行社团管理，但这些平台针对国外高校体系设计，本地化程度低，且多为付费产品，不适合国内高校直接使用。

**国内方面：** 国内的社团管理系统多以 Web 端为主，如基于 Java/Spring Boot 的社团管理后台、基于 PHP 的社团网站等。随着小程序生态的发展，近年来也出现了基于微信小程序的社团管理工具，但多数功能单一（仅签到或仅报名），缺乏完整的业务闭环。

**技术栈方面：** Node.js 作为服务端 JavaScript 运行时，在轻量级 API 开发中表现出色；MongoDB 作为 NoSQL 数据库，其文档型存储模式天然适合存储社团和活动的半结构化数据（如图片数组、标签列表、嵌套成员信息等）；Uniapp 基于 Vue.js 的跨平台框架，使前端开发效率显著提升。

### 1.3 研究内容与目标

本课题的主要研究内容包括：

1. **需求分析**：调研校园社团管理的实际需求，梳理业务流程和角色权限
2. **系统设计**：设计系统架构、数据模型、API 接口和前端页面结构
3. **系统实现**：基于 Uniapp + Node.js + Express + MongoDB 技术栈完成全栈开发
4. **系统测试**：编写自动化测试用例，验证功能完整性和业务规则正确性

系统目标：
- 实现社团信息数字化展示（成立时间、活动历史、成员信息、Logo）
- 实现社团创建审核流程（申请→审核→通过/拒绝→重新申请/撤回）
- 实现活动全生命周期管理（发布→报名→签到→评价）

- 实现站内消息通知系统（11种触发场景）
- 支持 H5 和微信小程序双端运行

## 第2章 相关技术介绍

### 2.1 Uniapp 跨平台开发框架

Uniapp 是 DCloud 公司推出的基于 Vue.js 的跨平台应用开发框架，使用 Vue.js 语法编写代码，可编译到 iOS、Android、H5、以及各种小程序等多个平台。本项目选择 Uniapp 的原因：

1. **一套代码多端运行**：同时支持 H5 和微信小程序，降低开发和维护成本
2. **Vue.js 生态**：可复用 Vue.js 丰富的组件和工具生态
3. **HBuilderX 集成开发**：提供可视化开发工具，支持一键编译和调试
4. **原生组件支持**：通过条件编译机制，可在特定平台使用原生能力

本项目采用 Vue 2 Options API 编写页面组件，使用 HBuilderX 作为主要开发工具，页面结构通过 `pages.json` 配置路由和 TabBar 导航。

### 2.2 Node.js 与 Express 框架

Node.js 是基于 Chrome V8 引擎的 JavaScript 运行时环境，采用事件驱动、非阻塞 I/O 模型，适合构建高并发的网络应用。Express 是 Node.js 最流行的 Web 框架，提供简洁的路由、中间件机制和 HTTP 工具。

本项目后端采用 Express 构建 RESTful API 服务，主要使用的中间件包括：

| 中间件 | 用途 |
|--------|------|
| cors | 处理跨域请求 |
| express.json | 解析 JSON 请求体 |
| morgan | HTTP 请求日志 |
| multer | 文件上传处理 |
| jsonwebtoken | JWT Token 认证 |
| bcryptjs | 密码加密 |
| express-validator | 请求参数校验 |

### 2.3 MongoDB 数据库

MongoDB 是一款开源的 NoSQL 文档型数据库，以 BSON（Binary JSON）格式存储数据。相比关系型数据库，MongoDB 具有以下优势：

1. **灵活的文档模型**：无需预定义严格的表结构，适合存储半结构化数据
2. **嵌套文档支持**：社团的成员列表可直接嵌套在社团文档中，减少关联查询
3. **数组字段**：活动的图片列表、标签列表等可直接存储为数组
4. **水平扩展能力**：支持分片集群，便于后续扩展

本项目通过 Mongoose ODM（Object Document Mapping）操作 MongoDB，Mongoose 提供了 Schema 定义、数据验证、中间件钩子等功能，简化了数据库操作。

### 2.4 JWT 认证机制

JSON Web Token（JWT）是一种轻量级的身份认证方案，适用于前后端分离架构。其工作流程为：

1. 用户登录成功后，服务端生成包含用户 ID 的 JWT Token
2. 客户端将 Token 存储在本地（uni.setStorageSync）
3. 后续请求在 HTTP Header 中携带 Token（Authorization: Bearer xxx）
4. 服务端验证 Token 有效性，识别用户身份

本项目 JWT Token 有效期设置为 7 天，过期后前端自动跳转登录页。

### 2.5 RESTful API 设计规范

本项目后端 API 遵循 RESTful 设计规范：

- 使用 HTTP 方法表示操作：GET（查询）、POST（创建）、PUT（更新）、DELETE（删除）
- 使用 URL 路径表示资源：`/api/clubs`（社团）、`/api/activities`（活动）
- 使用 HTTP 状态码表示结果：200（成功）、201（创建成功）、401（未认证）、403（无权限）、404（不存在）
- 统一响应格式：`{ code: 0, message: "操作成功", data: {...} }`

## 第3章 系统分析与设计

### 3.1 需求分析

#### 3.1.1 功能需求

通过对校园社团管理场景的调研分析，确定系统需要实现以下核心功能：

**（1）用户认证模块**：用户注册、登录、个人信息管理，采用 JWT Token 认证。

**（2）社团管理模块**：社团创建（需管理员审核）、编辑、信息展示（含成立时间、活动历史、成员列表、Logo、标签），社团分类（学术科技、文化艺术、体育运动、志愿公益、创新创业、其他）。

**（3）社团审核模块**：学生申请创建社团后状态为 pending，管理员审核通过后变为 active，拒绝时必须填写原因；申请人可查看拒绝原因、修改后重新提交、或撤回申请（彻底删除）。

**（4）成员管理模块**：加入社团、退出社团、角色管理（社长/副社长/成员）、社长转让、移除成员。

**（5）活动管理模块**：活动发布（社长/副社长）、编辑、删除、状态自动切换（基于时间自动从 published→ongoing→ended）。

**（6）活动报名模块**：支持自动通过和需审核两种模式、名额限制、防重复报名。活动进行中也允许报名。

**（7）签到打卡模块**：签到码验证机制（组织者生成6位数字码，参与者输入验码），签到时间校验（只允许活动进行期间签到），签到记录管理。

**（8）活动评价模块**：1-5分评分 + 文字评论，防重复评价，自动计算平均分。

**（9）图片存储模块**：社团 Logo、活动封面图、活动图片集的上传、展示、删除。

**（10）消息通知模块**：站内通知系统，覆盖社团审核、报名审核、成员变动等 11 种触发场景。

#### 3.1.2 角色分析

系统存在两层角色体系：

**系统级角色：**

| 角色 | 说明 | 获取方式 |
|------|------|---------|
| 普通学生（student） | 基础用户，可浏览、报名、签到、评价 | 注册时默认 |
| 社团管理员（club_admin） | 管理其社团 | 社团审核通过后自动升级 |
| 系统管理员（admin） | 全局管理权限 | 后台设置 |

**社团内角色：**

| 角色 | 说明 |
|------|------|
| 社长（president） | 社团最高管理者，可编辑社团、发布活动、管理成员、转让社长 |
| 副社长（vice_president） | 可发布活动 |
| 普通成员（member） | 参与社团活动 |

#### 3.1.3 非功能需求

- **跨平台**：同时支持 H5 和微信小程序
- **响应速度**：API 接口响应时间 < 500ms
- **安全性**：密码 bcrypt 加密存储，JWT Token 认证，权限校验
- **可维护性**：前后端分离，模块化设计，统一接口规范

系统采用经典的前后端分离三层架构：

```

│                 表现层（Uniapp）                   │
│            H5 / 微信小程序                        │

└────────────────────┬────────────────────────────┘
                     │ HTTP / JSON (RESTful API)
┌────────────────────▼────────────────────────────┐
```

### 3.3 数据库设计

系统共设计 7 个数据模型（MongoDB 集合）：

**（1）用户表（User）**

存储用户账号信息和角色标识。密码使用 bcryptjs 加密存储，通过 Mongoose 的 pre('save') 钩子自动加密。toJSON 方法自动过滤密码字段，防止泄露。

主要字段：username（唯一，2-20字符）、password（≥6字符，bcrypt加密）、nickname、avatar、phone、studentId、role（student/club_admin/admin）、openid（微信预留）。

**（2）社团表（Club）**

采用 MongoDB 嵌套文档存储成员列表，避免额外的关联表。每个成员子文档包含 user（关联 User）、role（president/vice_president/member）、joinedAt。

主要字段：name（唯一）、description、logo、foundedAt、category（6种分类）、president（关联 User）、members（子文档数组）、memberCount、status（active/inactive/pending）、announcement、tags（数组）、rejectReason。

**（3）活动表（Activity）**

支持活动图文存储，images 字段存储图片 URL 数组，coverImage 存储封面图 URL。签到码相关字段 checkinCode 和 checkinCodeEnabled 用于签到码验证功能。

主要字段：title、description、club（关联 Club）、organizer（关联 User）、startTime、endTime、location、maxParticipants、currentParticipants、images（数组）、coverImage、status（6种状态）、needApproval、tags（数组）、checkinCode、checkinCodeEnabled。

**（4）报名表（Registration）**

通过 `{ user, activity }` 唯一索引保证同一用户不能重复报名同一活动。

**（5）签到表（CheckIn）**

记录签到时间和位置信息，通过唯一索引防止重复签到。

**（6）评价表（Feedback）**

评分范围 1-5 分，通过唯一索引防止重复评价。

**（7）通知表（Notification）**

支持 10 种通知类型，read 字段标识已读/未读状态。

### 4.2 用户认证模块实现

用户注册时，系统通过 express-validator 校验参数（用户名 2-20 字符、密码≥6字符），密码通过 bcryptjs 的 pre('save') 钩子自动加密后存入数据库。登录时使用 bcrypt.compare 比对密码，验证通过后使用 jsonwebtoken 生成 JWT Token（有效期 7 天）返回给客户端。

认证中间件（auth）从请求头 Authorization 字段提取 Token，验证有效性后将用户信息挂载到 req.user，供后续路由使用。

前端使用 uni.setStorageSync 存储 Token 和用户信息，在 request.js 封装的请求方法中自动附加 Token 头。当收到 401 响应时自动清除存储并跳转登录页。

### 4.3 社团管理与审核模块实现

社团创建采用审核制：用户提交创建申请后社团状态为 pending，系统自动通知所有管理员。管理员审核通过后状态变为 active，申请人角色升级为 club_admin；拒绝时必须填写原因，原因存入 rejectReason 字段并随通知发送给申请人。

被拒绝的社团在"我的社团"页面显示红色"已拒绝"标记，用户点击可查看拒绝原因弹窗，选择"修改并重新提交"（跳转专用重新申请页面）或"取消申请"（彻底删除社团）。撤回时同步通知管理员。

社团详情页展示完整信息：Logo（有 Logo 显示图片，无 Logo 显示文字头像）、基本信息、公告、简介和标签、成员列表（按角色颜色区分）、活动历史。

### 4.4 活动管理模块实现

活动支持完整的生命周期管理。状态自动切换通过 activityStatus.js 工具实现：每次查询活动时自动比较当前时间与 startTime/endTime，将过期的活动状态更新为 ongoing 或 ended，无需定时任务。

活动创建页面支持设置标题、描述、时间、地点、名额上限、是否需要报名审核、封面图、标签等信息。活动编辑页面支持修改信息、切换状态和删除活动（删除时同步清除报名记录）。

### 4.5 签到码验证模块实现

签到码是本系统的特色功能，用于验证参与者到场：

1. **组织者端**：在签到记录管理页面点击"开启签到码"，系统生成随机 6 位数字码并大号显示。组织者可随时"刷新签到码"（旧码立即失效）。签到码一旦启用不可关闭回无码模式（防止未到场者事后补签），只能选择"结束签到"（活动标记为 ended，endTime 同步更新为当前时间）。

2. **参与者端**：点击"签到打卡"时，若活动未开启签到码则直接签到；若已开启则弹出输入框，输入正确的 6 位签到码后签到成功。

3. **后端校验**：签到接口依次检查活动状态、时间范围（startTime ≤ now ≤ endTime）、报名状态（必须 approved）、重复签到、签到码正确性。

### 4.6 消息通知模块实现

系统实现了站内通知中心，通过 notify.js 工具函数在关键业务事件触发时自动创建通知。通知分为三大类：

**审核类**（需处理）：创建社团→通知管理员、重新提交→通知管理员、报名需审核→通知组织者。

**结果类**（告知结果）：社团审核通过/拒绝→通知申请人、报名通过/拒绝→通知报名人。

**动态类**（信息同步）：成员加入/退出/角色变更/被移除→通知社长或当事人、撤回社团申请→通知管理员。

前端消息中心页面展示所有通知，未读消息蓝色背景 + 红点标记，点击通知自动标记已读并跳转到相关页面。"我的"页面消息入口显示未读数红色徽章。

### 4.7 图片存储模块实现

图片上传使用 multer 中间件处理文件，存储到服务器 uploads/ 目录，通过 Express 静态文件服务对外提供访问。上传时校验文件类型（仅允许 jpg/png/gif/webp）和大小（≤5MB）。

社团 Logo 在创建/编辑社团时上传，展示在首页卡片、社团列表、社团详情、我的社团四个位置。活动封面图展示在活动列表和活动详情页。活动图片集支持多图上传（最多9张），在活动详情页展示，组织者可单张删除。

## 第6章 总结与展望

### 6.1 研究总结

本文设计并实现了一套基于 Uniapp 的校园社团活动管理小程序系统，主要完成了以下工作：

1. **完成了系统需求分析和架构设计**：梳理了 3 种系统角色、3 种社团内角色、10 大功能模块、6 种活动状态的完整业务模型。

2. **实现了全栈开发**：前端 20 个页面、后端 43 个 API 接口、7 个数据模型，总代码量约 4700 行。

3. **设计了签到码验证机制**：创新性地实现了"组织者发码→参与者验码"的签到流程，签到码一旦启用不可关闭（只能刷新或结束），有效防止未到场补签。

4. **实现了完整的审核流程**：社团创建审核（申请→审核→重新提交/撤回）和报名审核（自动通过/人工审核）形成完整闭环。

5. **建立了站内消息通知系统**：覆盖 11 种业务场景的自动通知，确保各角色及时获取关键信息。

6. **通过了系统测试**：57 个自动化测试用例 100% 通过，34 个开发过程中发现的问题全部修复。

### 6.2 不足与展望

本系统仍存在以下不足，可在后续版本中改进：

1. **微信生态集成**：当前使用用户名密码登录，未集成微信授权登录（需要已认证的小程序 AppID）。
2. **数据统计分析**：缺少社团活跃度、活动参与率等数据统计和可视化展示。
3. **实时通信**：消息通知为拉取模式，未实现 WebSocket 实时推送。
4. **图片存储优化**：当前使用服务器本地存储，生产环境建议改用云存储（如阿里云 OSS）。
5. **搜索优化**：当前使用 MongoDB 正则匹配，大数据量下性能有限，可引入 Elasticsearch。
