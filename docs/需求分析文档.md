## 1. 项目概述

### 1.1 项目背景

适配移动端轻量化需求，采用 Uniapp 开发平台构建小程序，涵盖社团信息展示、活动发布与报名、社团成员管理、活动打卡与反馈等功能。后端使用 Node.js + Express 框架，数据库选用 MongoDB 存储半结构化的活动图文数据。

### 1.2 系统目标

| 目标 | 说明 |
|------|------|
| 社团信息数字化 | 展示社团成立时间、活动历史、成员信息 |
| 活动管理自动化 | 支持活动发布、名额限制、报名审核 |
| 成员管理规范化 | 招新、退社流程化，角色分级 |
| 活动反馈闭环化 | 签到打卡、活动评价一体化 |

### 1.3 系统架构

```
┌─────────────────────────────────────────────────┐
│                  客户端（Uniapp）                  │
│          H5 / 微信小程序 / App                     │
└────────────────────┬────────────────────────────┘
                     │ HTTP / JSON
┌────────────────────▼────────────────────────────┐
│              后端 API（Express.js）                │
│     认证 │ 社团 │ 成员 │ 活动 │ 签到 │ 评价       │
└────────────────────┬────────────────────────────┘
                     │ Mongoose ODM
┌────────────────────▼────────────────────────────┐
│                MongoDB 数据库                     │
│   users │ clubs │ activities │ registrations     │
│   checkins │ feedbacks                           │
└─────────────────────────────────────────────────┘
```

## 2. 系统角色定义

系统存在两层角色体系：**系统级角色**和**社团内角色**。

### 2.1 系统级角色（User.role）

| 角色标识 | 角色名称 | 获取方式 | 说明 |
|---------|---------|---------|------|
| `student` | 普通学生 | 注册时默认 | 基础用户角色，可浏览、报名、签到、评价 |
| `club_admin` | 社团管理员 | 创建社团时自动升级 | 拥有其所管理社团的管理权限 |
| `admin` | 系统管理员 | 后台手动设置 | 拥有所有操作的最高权限 |

### 2.2 社团内角色（Club.members[].role）

| 角色标识 | 角色名称 | 获取方式 | 说明 |
|---------|---------|---------|------|
| `president` | 社长 | 创建社团/社长任命 | 社团最高管理者 |
| `vice_president` | 副社长 | 社长任命 | 协助社长管理社团 |
| `member` | 普通成员 | 加入社团时默认 | 参与社团活动 |

### 2.3 角色关系说明

```
系统管理员 (admin)
  └── 拥有全局管理权限，可管理任意社团和活动

社团管理员 (club_admin) = 创建过社团的用户
  └── 作为社长管理自己创建的社团

普通学生 (student)
  ├── 可浏览所有公开信息
  ├── 可加入社团成为成员
  ├── 可报名参加活动
  └── 创建社团后升级为 club_admin

社团内部层级：
  社长 (president) > 副社长 (vice_president) > 普通成员 (member)
```

## 4. 功能模块详解

### 4.1 用户认证模块

| 功能 | 说明 |
|------|------|
| 用户注册 | 提供用户名、密码（≥6位）、昵称、学号，密码 bcrypt 加密存储 |
| 用户登录 | 用户名 + 密码验证，返回 JWT Token（有效期 7 天） |
| 个人信息 | 查看/修改昵称、头像、手机号、学号 |
| Token 认证 | 请求头 `Authorization: Bearer <token>`，自动识别用户身份 |

### 4.2 社团管理模块

| 功能 | 说明 |
|------|------|
| 社团列表 | 分页查询，支持按分类筛选和关键词搜索，仅展示状态为 active 的社团 |
| 社团详情 | 展示社团名称、简介、分类、成立时间、成员列表、公告 |
| **社团活动历史** | **在社团详情页展示该社团组织过的所有活动列表（含进行中和已结束），展示活动轨迹** |
| 创建社团 | 设置名称、简介、分类、Logo、成立时间、标签，创建者自动成为社长 |
| 编辑社团 | 社长或管理员可修改社团信息、发布公告、修改状态 |

**社团分类：** 学术科技、文化艺术、体育运动、志愿公益、创新创业、其他

### 4.3 成员管理模块

| 功能 | 说明 |
|------|------|
| 加入社团 | 登录用户可加入任意活跃社团，防重复加入 |
| 退出社团 | 普通成员/副社长可自行退出，社长不能退出（需先转让） |
| 角色管理 | 社长可设置成员为副社长或普通成员 |
| 移除成员 | 社长或系统管理员可移除社团成员 |
| 成员查询 | 查看社团成员列表，包含昵称、头像、学号、手机 |

### 4.4 活动管理模块

| 功能 | 说明 |
|------|------|
| 活动列表 | 分页查询，支持按状态、所属社团、关键词筛选 |
| 活动详情 | 展示标题、描述、时间、地点、人数、报名列表 |
| 创建活动 | 社长/副社长设置活动信息，可选择是否需要报名审核 |
| 编辑活动 | 组织者或管理员修改活动信息（含状态变更） |
| 删除活动 | 组织者或管理员删除活动，同时清除相关报名记录 |

**活动状态流转：** `draft（草稿）` → `published（已发布/报名中）` → `registration（报名中）` → `ongoing（进行中）` → `ended（已结束）`；任意阶段可 → `cancelled（已取消）`

### 4.5 活动报名模块

| 功能 | 说明 |
|------|------|
| 活动报名 | 用户对报名中的活动提交报名申请 |
| 名额限制 | maxParticipants > 0 时检查是否超出名额 |
| 报名审核 | needApproval=true 时需组织者/管理员审核（通过/拒绝） |
| 自动通过 | needApproval=false 时报名自动通过，计数 +1 |

**报名状态：** `pending（待审核）` → `approved（已通过）` / `rejected（已拒绝）`；用户可 → `cancelled（已取消）`

### 4.6 签到打卡模块

| 功能 | 说明 |
|------|------|
| 活动签到 | 报名已通过的用户可在活动期间签到 |
| 位置记录 | 可携带经纬度坐标信息 |
| 签到查询 | 查看活动的所有签到记录 |
| 签到状态 | 查询当前用户是否已签到某活动 |

### 4.7 活动评价模块

| 功能 | 说明 |
|------|------|
| 提交评价 | 已签到用户可对活动评分（1-5分）并撰写评论 |
| 评价列表 | 分页查看活动的所有评价，包含平均评分 |
| 防重复 | 每人每活动仅可评价一次 |

### 4.8 图片存储模块

> 课题要求："数据库选用 MongoDB 存储**半结构化的活动图文数据**"

| 功能 | 说明 |
|------|------|
| 图片上传 | 支持上传社团 Logo、活动封面图、活动详情图片，存储到服务器本地 `uploads/` 目录 |
| 社团 Logo | 创建/编辑社团时可上传社团 Logo 图片 |
| 活动封面图 | 创建/编辑活动时可设置活动封面图（coverImage），用于列表卡片展示 |
| 活动图片集 | 创建/编辑活动时可上传多张活动详情图片（images 数组），用于活动详情页图文展示 |
| 图片访问 | 上传的图片通过静态文件服务对外提供 HTTP 访问地址 |

**存储方式：** 服务器本地文件存储 + MongoDB 记录图片 URL 路径

## 8. 业务规则与约束

### 8.1 用户相关

| 编号 | 规则 |
|------|------|
| U-01 | 用户名全局唯一，长度 2-20 字符 |
| U-02 | 密码最少 6 字符，使用 bcrypt 加密存储 |
| U-03 | JWT Token 有效期 7 天 |
| U-04 | Token 过期自动跳转登录页 |
| U-05 | 密码字段在返回 JSON 时自动过滤 |

### 8.2 社团相关

| 编号 | 规则 |
|------|------|
| C-01 | 社团名称全局唯一 |
| C-02 | 列表仅展示状态为 active 的社团 |
| C-03 | 创建社团的用户自动成为社长，角色升级为 club_admin |
| C-04 | 一个用户可加入多个社团 |
| C-05 | 不可重复加入同一社团 |
| C-06 | 社长不能退出自己的社团（需先转让社长） |
| C-07 | memberCount 字段在加入/退出时自动维护 |

### 8.3 活动相关

| 编号 | 规则 |
|------|------|
| A-01 | 只有社团的社长或副社长可以发布活动 |
| A-02 | 活动必须关联一个社团 |
| A-03 | maxParticipants=0 表示不限名额 |
| A-04 | 删除活动时同步删除该活动所有报名记录 |

### 8.4 报名相关

| 编号 | 规则 |
|------|------|
| R-01 | 同一用户同一活动只能报名一次（唯一索引保证） |
| R-02 | 仅活动状态为 published/registration 时可报名 |
| R-03 | 有名额限制时检查 currentParticipants < maxParticipants |
| R-04 | needApproval=false 时自动通过并增加计数 |
| R-05 | needApproval=true 时状态为 pending，需组织者审核 |
| R-06 | 审核通过时增加活动参与人数计数 |

### 8.5 签到相关

| 编号 | 规则 |
|------|------|
| K-01 | 同一用户同一活动只能签到一次（唯一索引保证） |
| K-02 | 签到前提：报名状态为 approved |
| K-03 | 活动状态需为 published/registration/ongoing |
| K-04 | 签到自动记录当前时间 |

### 8.6 评价相关

| 编号 | 规则 |
|------|------|
| F-01 | 同一用户同一活动只能评价一次（唯一索引保证） |
| F-02 | 评分范围 1-5 分（整数） |
| F-03 | 评价列表自动计算平均分 |
| F-04 | 前端限制仅签到后可评价 |
