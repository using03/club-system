## 1. 项目概述

### 1.1 项目背景

适配移动端轻量化需求，采用 Uniapp 开发平台构建小程序，涵盖社团信息展示、活动发布与报名、社团成员管理、签到码签到、活动反馈、消息通知等功能。后端使用 Node.js + Express 框架，数据库选用 MongoDB 存储半结构化的活动图文数据。

### 1.2 系统目标

| 目标 | 说明 |
|------|------|
| 社团信息数字化 | 展示社团成立时间、活动历史、成员信息、Logo、标签 |
| 社团审核规范化 | 社团创建需管理员审核，支持拒绝原因说明、重新提交、撤回申请 |
| 活动管理自动化 | 支持活动发布、名额限制、报名审核、签到码签到 |
| 成员管理规范化 | 加入、退社流程化，角色分级（社长/副社长/成员） |
| 活动反馈闭环化 | 签到码打卡、活动评价一体化 |
| 消息通知实时化 | 社团审核、报名审核、成员变动等关键事件自动推送通知 |

### 1.3 系统架构

```
┌─────────────────────────────────────────────────┐
│                  客户端（Uniapp）                  │
│          H5 / 微信小程序 / App                     │
└────────────────────┬────────────────────────────┘
                     │ HTTP / JSON
┌────────────────────▼────────────────────────────┐
│              后端 API（Express.js）                │
│  认证│社团│成员│活动│签到│评价│上传│通知           │
└────────────────────┬────────────────────────────┘
                     │ Mongoose ODM
┌────────────────────▼────────────────────────────┐
│                MongoDB 数据库                     │
│  users│clubs│activities│registrations            │
│  checkins│feedbacks│notifications                │
└─────────────────────────────────────────────────┘
```

## 2. 系统角色定义

系统存在两层角色体系：**系统级角色**和**社团内角色**。

### 2.1 系统级角色（User.role）

| 角色标识 | 角色名称 | 获取方式 | 说明 |
|---------|---------|---------|------|
| `student` | 普通学生 | 注册时默认 | 基础用户角色，可浏览、报名、签到、评价 |
| `club_admin` | 社团管理员 | 创建社团且审核通过后自动升级 | 拥有其所管理社团的管理权限 |
| `admin` | 系统管理员 | 后台手动设置 | 拥有所有操作的最高权限，可审核社团申请 |

### 2.2 社团内角色（Club.members[].role）

| 角色标识 | 角色名称 | 获取方式 | 说明 |
|---------|---------|---------|------|
| `president` | 社长 | 创建社团/社长任命 | 社团最高管理者 |
| `vice_president` | 副社长 | 社长任命 | 协助社长管理社团 |
| `member` | 普通成员 | 加入社团时默认 | 参与社团活动 |

### 2.3 角色关系说明

```
系统管理员 (admin)
  └── 拥有全局管理权限，可审核社团申请、管理任意社团和活动

社团管理员 (club_admin) = 创建过社团且审核通过的用户
  └── 作为社长管理自己创建的社团

普通学生 (student)
  ├── 可浏览所有公开信息
  ├── 可加入社团成为成员
  ├── 可报名参加活动
  └── 创建社团提交申请，审核通过后升级为 club_admin

社团内部层级：
  社长 (president) > 副社长 (vice_president) > 普通成员 (member)
```

## 4. 功能模块详解

### 4.1 用户认证模块

| 功能 | 说明 |
|------|------|
| 用户注册 | 提供用户名、密码（≥6位）、昵称、学号，密码 bcrypt 加密存储，昵称默认为用户名 |
| 用户登录 | 用户名 + 密码验证，返回 JWT Token（有效期由环境变量 JWT_EXPIRES_IN 配置） |
| 个人信息 | 查看/修改昵称、头像、手机号、学号 |
| Token 认证 | 请求头 `Authorization: Bearer <token>`，自动识别用户身份 |
| 我的社团 | 查看当前用户加入的所有社团列表 |
| 我的活动 | 查看当前用户报名的所有活动，未签到的排前面、已签到的排后面 |
| 我的报名 | 查看当前用户的所有报名记录 |
| 我的签到 | 查看当前用户的所有签到记录 |

### 4.2 社团管理模块

| 功能 | 说明 |
|------|------|
| 社团列表 | 分页查询，支持按分类筛选和关键词搜索，仅展示状态为 active 的社团，展示 Logo 和标签 |
| 社团详情 | 展示社团名称、简介、Logo、分类、标签、成立时间、成员列表、公告 |
| 社团活动历史 | 在社团详情页展示该社团组织过的所有活动列表，按开始时间倒序 |
| 创建社团 | 设置名称、简介、分类、Logo、成立时间、标签，创建后状态为 pending，需管理员审核 |
| 编辑社团 | 社长或管理员可修改社团信息、发布公告、修改标签 |
| 待审核列表 | 管理员可查看所有待审核（pending）的社团列表 |
| 审核通过 | 管理员审核通过后社团状态变为 active，创建者角色升级为 club_admin |
| 审核拒绝 | 管理员拒绝时需填写拒绝原因，社团状态变为 inactive |
| 重新提交 | 被拒绝的社团申请人可修改信息后重新提交审核（inactive → pending） |
| 撤回申请 | 申请人可撤回未通过审核的社团申请（永久删除社团及其活动） |

**社团分类（6类）：** 学术科技、文化艺术、体育运动、志愿公益、创新创业、其他

**社团状态流转：** `pending（待审核）` → 管理员通过 → `active（活跃）`；管理员拒绝 → `inactive（未通过）` → 修改重新提交 → `pending`；任意非 active 状态可撤回（删除）

### 4.3 成员管理模块

| 功能 | 说明 |
|------|------|
| 加入社团 | 登录用户可加入任意活跃社团，防重复加入，加入后通知社长 |
| 退出社团 | 普通成员/副社长可自行退出，社长不能退出（需先转让），退出后通知社长 |
| 角色管理 | 社长可设置成员为副社长或普通成员 |
| 移除成员 | 社长或系统管理员可移除社团成员 |
| 成员查询 | 查看社团成员列表，包含昵称、头像、学号、手机 |

### 4.4 活动管理模块

| 功能 | 说明 |
|------|------|
| 活动列表 | 分页查询，支持按状态、所属社团、关键词筛选，展示封面图和标签 |
| 活动详情 | 展示标题、描述、时间、地点、人数、封面图（圆角，点击可预览）、活动图片集、标签、报名列表 |
| 创建活动 | 社长/副社长设置活动信息，可选择是否需要报名审核，可上传封面图和活动图片 |
| 编辑活动 | 组织者或管理员修改活动信息（含状态变更），可替换或删除封面图，可删除活动图片（需确认） |
| 删除活动 | 组织者或管理员删除活动，同时清除该活动所有报名记录 |

**活动状态流转：** `draft（草稿）` → `published（已发布）` → `registration（报名中）` → `ongoing（进行中）` → `ended（已结束）`；任意阶段可 → `cancelled（已取消）`

### 4.5 活动报名模块

| 功能 | 说明 |
|------|------|
| 活动报名 | 用户对 published/registration 状态的活动提交报名申请 |
| 名额限制 | maxParticipants > 0 时检查是否超出名额 |
| 报名审核 | needApproval=true 时需组织者/管理员审核（通过/拒绝），审核结果通知用户 |
| 自动通过 | needApproval=false 时报名自动通过，计数 +1，自动通知用户报名成功 |
| 待审核通知 | needApproval=true 时向组织者发送待审核通知 |

**报名状态：** `pending（待审核）` → `approved（已通过）` / `rejected（已拒绝）`；用户可 → `cancelled（已取消）`

### 4.6 签到打卡模块

| 功能 | 说明 |
|------|------|
| 签到码生成 | 组织者可为活动生成 6 位数字签到码，启用后不可禁用（只能刷新或停止） |
| 签到码刷新 | 组织者可重新生成新的签到码（覆盖原码） |
| 停止签到 | 组织者停止签到后，活动状态自动变为 ended，签到码清空 |
| 活动签到 | 报名已通过的用户在 ongoing/published/registration 状态下可签到 |
| 签到码校验 | 签到码启用时，用户必须输入正确的签到码才能完成签到 |
| 位置记录 | 签到时可携带经纬度坐标信息 |
| 签到查询 | 查看活动的所有签到记录（公开） |
| 签到状态 | 查询当前用户是否已签到某活动 |

### 4.7 活动评价模块

| 功能 | 说明 |
|------|------|
| 提交评价 | 已签到用户可对活动评分（1-5分）并撰写评论 |
| 评价列表 | 分页查看活动的所有评价，包含平均评分（保留一位小数） |
| 防重复 | 每人每活动仅可评价一次 |

### 4.8 图片上传模块

> 课题要求："数据库选用 MongoDB 存储**半结构化的活动图文数据**"

| 功能 | 说明 |
|------|------|
| 图片上传 | 支持上传社团 Logo、活动封面图、活动详情图片，存储到服务器本地 `uploads/` 目录 |
| 单张上传 | 上传单张图片，返回图片 URL |
| 批量上传 | 上传多张图片（最多9张），返回 URL 数组 |
| 文件限制 | 仅允许 jpg/jpeg/png/gif/webp 格式，单文件最大 5MB |
| 社团 Logo | 创建/编辑社团时可上传社团 Logo 图片，展示于首页卡片、社团列表、社团详情、我的社团 |
| 活动封面图 | 创建/编辑活动时可设置活动封面图（coverImage），展示于活动列表、活动详情（圆角，可点击预览），可替换或删除 |
| 活动图片集 | 创建/编辑活动时可上传多张活动详情图片（images 数组），组织者可删除图片（需确认对话框） |
| 图片访问 | 上传的图片通过静态文件服务对外提供 HTTP 访问地址 |

**存储方式：** 服务器本地文件存储 + MongoDB 记录图片 URL 路径

### 4.9 消息通知模块

| 功能 | 说明 |
|------|------|
| 通知列表 | 分页查看当前用户的所有通知，按时间倒序排列 |
| 未读计数 | 查询当前用户未读通知数量 |
| 标记已读 | 将单条通知标记为已读 |
| 全部已读 | 将当前用户所有未读通知一键标记为已读 |

**通知触发场景：**

| 事件 | 通知类型 | 接收人 |
|------|---------|--------|
| 创建社团（提交审核） | club_pending | 所有系统管理员 |
| 社团审核通过 | club_approved | 申请人（社长） |
| 社团审核拒绝 | club_rejected | 申请人（社长） |
| 社团撤回申请 | club_withdrawn | 所有系统管理员 |
| 社团重新提交审核 | club_pending | 所有系统管理员 |
| 报名自动通过 | registration_approved | 报名用户 |
| 报名待审核 | registration_pending | 活动组织者 |
| 报名审核通过 | registration_approved | 报名用户 |
| 报名审核拒绝 | registration_rejected | 报名用户 |
| 成员加入社团 | member_joined | 社长 |
| 成员退出社团 | member_left | 社长 |

## 8. 业务规则与约束

### 8.1 用户相关

| 编号 | 规则 |
|------|------|
| U-01 | 用户名全局唯一，长度 2-20 字符 |
| U-02 | 密码最少 6 字符，使用 bcrypt（salt=10）加密存储 |
| U-03 | JWT Token 有效期由环境变量 JWT_EXPIRES_IN 配置 |
| U-04 | Token 过期自动跳转登录页 |
| U-05 | 密码字段在返回 JSON 时自动过滤（toJSON 方法） |
| U-06 | 注册时如未提供昵称，默认使用用户名作为昵称 |

### 8.2 社团相关

| 编号 | 规则 |
|------|------|
| C-01 | 社团名称全局唯一 |
| C-02 | 列表仅展示状态为 active 的社团 |
| C-03 | 创建社团时状态为 pending，需管理员审核通过后变为 active |
| C-04 | 审核通过时，创建者角色从 student 升级为 club_admin |
| C-05 | 审核拒绝时需填写拒绝原因，状态变为 inactive |
| C-06 | 被拒绝的社团可修改后重新提交（inactive → pending），并通知管理员 |
| C-07 | 申请人可撤回未通过的社团申请（永久删除社团及其活动），并通知管理员 |
| C-08 | 已通过审核的社团（active）不能撤回 |
| C-09 | 一个用户可加入多个社团 |
| C-10 | 不可重复加入同一社团 |
| C-11 | 社长不能退出自己的社团（需先转让社长） |
| C-12 | memberCount 字段在加入/退出/移除时自动维护 |
| C-13 | 标签展示于社团列表、社团详情 |
| C-14 | Logo 展示于首页卡片、社团列表、社团详情、我的社团 |

### 8.3 活动相关

| 编号 | 规则 |
|------|------|
| A-01 | 只有社团的社长或副社长（或系统管理员）可以发布活动 |
| A-02 | 活动必须关联一个社团 |
| A-03 | maxParticipants=0 表示不限名额 |
| A-04 | 删除活动时同步删除该活动所有报名记录 |
| A-05 | 活动封面图展示于活动列表、活动详情（圆角，可点击预览） |
| A-06 | 活动图片可由组织者删除（需确认对话框） |
| A-07 | 封面图可在编辑页替换或删除 |
| A-08 | 标签展示于活动列表、活动详情、首页卡片 |

### 8.4 报名相关

| 编号 | 规则 |
|------|------|
| R-01 | 同一用户同一活动只能报名一次（唯一索引保证） |
| R-02 | 仅活动状态为 published/registration 时可报名 |
| R-03 | 有名额限制时检查 currentParticipants < maxParticipants |
| R-04 | needApproval=false 时自动通过并增加计数，通知用户报名成功 |
| R-05 | needApproval=true 时状态为 pending，通知组织者审核 |
| R-06 | 审核通过时增加活动参与人数计数，通知报名用户 |
| R-07 | 审核拒绝时通知报名用户 |

### 8.5 签到相关

| 编号 | 规则 |
|------|------|
| K-01 | 同一用户同一活动只能签到一次（唯一索引保证） |
| K-02 | 签到前提：报名状态为 approved |
| K-03 | 活动状态需为 ongoing/published/registration |
| K-04 | 签到自动记录当前时间 |
| K-05 | 签到码为 6 位随机数字，由组织者生成 |
| K-06 | 签到码启用后不可禁用，只能刷新（重新生成）或停止签到 |
| K-07 | 签到码启用时，用户必须输入正确签到码才能签到 |
| K-08 | 停止签到时活动状态自动变为 ended，签到码清空 |

### 8.6 评价相关

| 编号 | 规则 |
|------|------|
| F-01 | 同一用户同一活动只能评价一次（唯一索引保证） |
| F-02 | 评分范围 1-5 分（整数） |
| F-03 | 评价列表自动计算平均分（保留一位小数） |
| F-04 | 前端限制仅签到后可评价 |

### 8.7 通知相关

| 编号 | 规则 |
|------|------|
| N-01 | 社团创建申请提交后通知所有系统管理员 |
| N-02 | 社团审核通过/拒绝后通知申请人 |
| N-03 | 社团撤回申请后通知所有系统管理员 |
| N-04 | 社团重新提交审核后通知所有系统管理员 |
| N-05 | 报名自动通过时通知报名用户 |
| N-06 | 报名需审核时通知活动组织者 |
| N-07 | 报名审核通过/拒绝后通知报名用户 |
| N-08 | 成员加入/退出社团后通知社长 |
| N-09 | 我的活动列表按签到状态排序：未签到在前，已签到在后 |

### 8.8 图片相关

| 编号 | 规则 |
|------|------|
| I-01 | 仅支持 jpg/jpeg/png/gif/webp 格式 |
| I-02 | 单文件最大 5MB |
| I-03 | 批量上传最多 9 张 |
| I-04 | 图片存储于服务器本地 uploads/ 目录 |
| I-05 | 通过静态文件服务提供 HTTP 访问 |
